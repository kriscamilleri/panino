# API keys and the v1 Document API for LLMs

- Agent: Claude Code (Opus 5.5)
- Start: 2026-11-06, 10:44
- Status: Implemented and verified locally on `feature/llm-api-keys`; not merged

## Objective

Kris asked to make Panino easy for LLMs to use: let a user generate an API key that
authenticates queries against their database and spaces, evaluate whether every existing
endpoint is safe to expose that way, consider simplified endpoints, write a spec, ask for
feedback, then implement on a feature branch and test locally with screenshot evidence.

## Progress

- Found that Panino has no REST API for content at all: Documents and folders only move
  through `/sync` as CR-SQLite change sets. So the "simplified endpoints" are the LLM API, and
  exposing `/sync` is not an option (an agent would have to fabricate clock metadata).
- Evaluated every route group (spec §4). Conclusion: no existing route accepts a key. Keys
  authenticate a new `/v1` namespace only; `/v1` accepts no session JWT.
- Spec written at `docs/specs/proposed/llm-api.md`, then asked three questions. Kris decided
  (2026-11-06): **soft delete into a Trash folder** (a real delete cascades revision history
  away); keys reach **all databases or personal only**; **REST + OpenAPI now, MCP on a
  follow-up branch**. Spec moved to `active/` with the decisions recorded.
- Changed while building, recorded in the spec: an existing Document can be addressed without
  `space` (the server finds it among reachable databases); the pre-write revision is
  unattributed and deduplicated; the revision panel says "via API".
- Browser check found two defects, both fixed:
  - The one-time secret was still shown after leaving Settings and coming back (the store kept
    it). `ApiKeysSection` now forgets it on unmount; test added.
  - In dark mode `.pn-alert-success/-warning/-error` text kept its light-theme colour (applied
    through `@apply`, which the dark class remaps never match): dark green on dark green.
    Added dark-theme text colours for the three alert variants in `main.css`; checked the
    computed colours (light text on dark fill for all three). This affects every alert in
    the app, not only the new section.
