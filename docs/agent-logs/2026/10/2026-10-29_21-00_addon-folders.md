# Add-on folders: Odoo into its own folders, core reaches it only through the registry

- Agent: Claude Code (Opus 5.5)
- Start: 2026-10-29, approximately 20:30
- Status: Implemented and verified locally; not committed

## Objective

Make the add-on system modular, so an add-on is contained in its own folder, and core code no
longer names Odoo. Kris asked whether a single `./addons/odoo` folder was possible and worth it.
The answer, written up as [`addon-folders.md`](../../../specs/active/addon-folders.md), was one
folder per layer plus extension points in core. A single top-level folder breaks Node's package
resolution and needs Vite, Tailwind, Docker and lockfile changes for little gain. Kris approved
the spec with three decisions: rename test ids, confirm the phone modal host, and keep specs in
`docs/specs/` with a README per add-on folder.

## Progress

- Committed the pending sales-order-blocks work first (`941c77e`), with Kris's go-ahead, so the
  refactor could be reviewed as its own change.
- Confirmed the phone modal host question by reading the code. `HomePage` renders either
  `PhoneShell` or the desktop layout, and the Odoo modals were only in the desktop branch. On a
  phone they live inside `DocumentMenuSheet`, stacked over the open sheet. So the spec uses two
  hosts that are never on screen together.
- Backend: `git mv` of `addons.js` → `addons/registry.js` and of the twelve `odoo*.js` modules
  and their tests into `addons/odoo/`. Imports were rewritten with a scratch script that resolves
  each specifier against the file's old location and maps it to the new one.
- Frontend: `git mv` of the Odoo components, store, utils, composable and tests into
  `src/addons/odoo/`. Imports were rewritten with `sed` on the `@/` paths.
- A first attempt registered the add-ons in `tests/setup.js`. That broke `tests/unit/spaces.test.js`,
  `tests/integration/spaces.lifecycle.test.js` and `tests/integration/pdf.queue.test.js` (54
  tests): the Odoo routes loaded `spaces.js` and `pdf.js` against the real modules before those
  files could `vi.mock` them. Reverted. Integration tests already get the add-ons through
  `createTestApp()`, and no Odoo unit test needs Odoo tables. Recorded in the spec (§5.3) and the
  backend handbook.
- The boundary rule was first planned as `no-restricted-imports`, but that matches import strings,
  not resolved paths. It became a small local rule instead (spec §7).
