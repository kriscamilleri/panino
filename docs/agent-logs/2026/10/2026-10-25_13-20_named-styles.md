# Named preview and print styles with folder and template defaults

- Agent: Claude Code (Opus 5.5)
- Started: 2026-10-25 13:20
- Status: implemented on `feature/named-styles`; not yet pushed or opened as a PR

## Objective

Let users save, name and reuse preview and print styles, and set them as defaults on a folder
or a template. Spec: `docs/specs/active/named-styles.md`.

Decisions taken with the user before building: preview and print styles are separate kinds;
a template stamps `preview-style:` / `print-style:` front matter into new Documents; named
styles belong to a library (personal or Space), like templates.

## Progress

1. Spec written, with journeys U1–U9.
2. Pure helpers: `utils/frontMatter.js` (parser moved out of `markdownStore`, plus a writer),
   `utils/styleDefaults.js` (built-in styles and the print stylesheet builder, moved out of
   `markdownStore`), `utils/stylePresets.js` (names, assignment ids, value parsing, resolution).
3. Schema: new CRR tables `style_presets` and `style_assignments` in `DB_SCHEMA`,
   `BASE_SCHEMA` and `CRR_TABLES`, and in both Space allowlists. No existing CRR was altered;
   `CONTENT_SCHEMA_VERSION` was not raised.
4. Store: `stylePresetStore` (CRUD, assignments, resolution for the selected Document via its
   folder trail; reloaded after every sync from `docStore.refreshData`).
5. UI: `StylePresetBar` on both style pages via `useStyleEditing`; `FolderStylesModal` from the
   desktop tree folder menu and the phone folder options sheet; two selects in the template
   editor; the template picker stamps front matter; `Preview.vue` and the phone Export sheet
   render with the resolved style.

## Changes Made

See `git log main..feature/named-styles`. Two races found in browser testing and fixed:

- `FolderStylesModal` read the folder's current defaults after opening and overwrote a choice
  made in the meantime, so Save saved nothing. The selects and Save are now disabled until the
  defaults are read.
- `TemplateManagerPage` could open a template before its defaults had loaded; saving then would
  clear them. `openEdit` now waits for the load.

## Open Items / Notes

- The developer's own dev stack (`docker-compose.dev.yml`) API container has no reload on
  change, so it needs a restart before named styles sync there; until then a client that saves a
  style gets a merge failure from the old server.
- Rollout: a client that has not reloaded since the deploy cannot apply pulled rows for the new
  tables, so its sync stalls until the service worker update reloads it (about a minute).
- Follow-ups: include named styles in JSON/ZIP export; copy a template's defaults when it is
  duplicated; Space templates have no UI for defaults (the template manager edits personal
  templates only).
- Headless Chromium does not draw PDFs inside the iframe, so the PDF itself was checked through
  the request body, not visually.
